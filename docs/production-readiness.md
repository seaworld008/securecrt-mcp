# 生产运行边界与交付门槛

当前实现为Rust核心、Windows JScript原生桥接、Mac最小Python原生层和JS开发/验收工具。安装流程见[一键安装](installation.md)，实际覆盖见[支持矩阵](support-matrix.md)。旧版本回执只证明其确切源码和设备，不自动认证新提交。

交付需要分别取得：

- 格式、严格Clippy、锁定Rust测试、编译后的Node MCP/故障/性能/daemon/打包门槛。
- 实际客户端至少两个获准空闲POSIX Tab的D01–D14矩阵，原定10秒2,500行中文逐行完整。
- 原生UI U01–U04：启动、重复提示及原实例继续响应、空闲取消保持登录、重载新句柄、专用连接断开重连拒绝旧附件。
- 脱敏源码/二进制/桥接身份、修改状态、实际引擎、数量、耗时、每项PASS/FAIL/未测。
- 精确提交PR、全部必需CI成功、清除未解决审查线程、按精确HEAD合并并核对远端main。

部署时核对来源和摘要，执行`install`，重新加载MCP并闲时重载固定原生入口；先对明确非业务Tab验收。`doctor --offline`不建立远端连接，在线doctor也不替代完整执行/UI证明。

`shared/exclusive/observe`只是连接器协作模式，不是系统键盘锁。元数据和屏幕不能证明嵌套SSH主机身份；`completed`只证明该前台命令结束标记，不证明所有后台后代结束。daemon与内存operation缓存不是跨重启永久事务数据库。

超时、未知投递、捕获失败、上下文改变均先检查原Tab，不重放、不自动Ctrl+C或自动ack。错误提示符、观察模式、输入边界冲突必须拒绝且零发送。本地危险命令过滤不是完整Shell分析器或远端沙箱；客户端审批与远端最小权限仍有效，安装不会放宽既有审批设置。

问题回执公开前脱敏，保留原FAIL审计和本地私有诊断。测试、CI、真机GUI、远端业务验证分别陈述；未完成项不能称作最终通过。
