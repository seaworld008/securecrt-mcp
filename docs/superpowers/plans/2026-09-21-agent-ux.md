# Agent-first command experience

## Approved intent

The user wants a connection tool for existing authenticated SecureCRT sessions, not a second command-authorization system. Preserve the tested protocol-2 path and Windows acceptance record. Add a convenient one-call path, observable outcomes, and standard local clients; then validate and integrate via PR.

## Design and boundaries

- `securecrt_run_command` orchestrates a fresh read, context check, one submission, bounded waiting and bounded output. Explicit capture mode is required; POSIX is not silently selected for an appliance/REPL. No automatic retries, Ctrl+C or acknowledgement of unresolved work.
- Keep low-level tools compatible. Operation identifiers deduplicate within one MCP process; neither reconnect nor new processes imply exactly-once remote execution.
- Report `sent` as true/false/null. Only explicit adapter rejection before a send proves false. Lost replies remain unknown; current local code must not quarantine an operation proven unsent.
- Add `client` policy for command-risk decisions delegated to the client. New installs use it; upgrade preserves existing policy verbatim. Preserve optional local modes/rules, raw-input opt-in, framing, target binding and audit controls.
- Return a fresh view after an explicit idle acknowledgement. Never acknowledge simply because a client disconnected.
- Ship a Rust one-shot CLI and thin Python/PowerShell wrappers. Native MCP is the preferred persistent interface; the CLI remains alive until its submitted operation terminates locally.

## Execution plan

1. Add regressions for unsent rejection, send uncertainty, fresh context after acknowledgement, single-call command execution, deduplication, input limits and client-mode policy. Run new regressions against unchanged implementation and retain RED evidence.
2. Add typed transport errors and adapter send-outcome metadata. Fix lifecycle outcomes without converting ambiguous delivery into not-sent.
3. Add high-level execution using the existing engine, bounded wait/output, explicit modes and consistent recovery information. Fix result-state and partial-output edge cases covered by tests.
4. Add client policy, policy diagnostics, configurable Codex approval generation and a concise tool preset. Existing configuration is not rewritten.
5. Add standard clients, document migration and preserve the user's historical runtime evidence. Run all existing and new tests, strict Clippy, three-platform CI and inspect the final diff.
6. Create and merge a PR only after final-head checks pass, then verify main. Do not create a release tag.

## Review focus

Concurrent calls must not invalidate a token and turn zero sends into an unresolved job. An unknown response must not trigger re-execution. Password/pager/continuation prompts must not be silently treated as a POSIX shell. Large Unicode output must remain bounded. CLI lifetime and string escaping must be exercised on Windows. Tests do not certify actual desktop approval UIs.
