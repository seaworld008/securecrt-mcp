# securecrt-mcp 0.5.6

本轮检查 Mac SecureCRT 真机路径，并修复共享执行、安全恢复和脚本传输的缺陷。既有审批、策略、令牌和 SSH 登录保持。

## 修复

- OpenSSH 命令、原始输入和显式中断遵守已有操作者策略，并在发送前写入审计；审计失败拒绝发送。批次提前校验全部命令，拒绝时没有部分发送。
- Mac 空闲恢复只能使用新鲜完整屏幕令牌，附件标识不能绕过屏幕与提示符校验。
- Mac 切换原生 Tab 后先让事件循环处理输入通道，再重新检查身份和输入上下文。没有延长 10 秒输出捕获预算，也不会重放未知命令。
- Rust 复用已确认支持持久连接的 TCP 通道；错误、断连或无持久协商时丢弃连接，不重试请求。
- 新生成 Codex 终端配置包含提示符恢复工具；已有工具限制继续保留。Windows 恢复能力检查绑定目标实例，支持混合版本进程。
- 脚本分块传输兼容 GNU/Linux 与 macOS BSD 命令，支持 `shasum`，从标准输入计算摘要以避免反斜杠文件名的输出差异。遇到不确定结果继续保留暂存，不自动重传或清理。

## 验证范围

锁定 Rust 49 项测试、编译后 MCP/Node 与 Mac 91 项原生适配器契约通过。[Mac 真机回执](../acceptance/mac-native-matrix-2026-10-14.md)记录干净修复提交 `036a5e5`、精确二进制/桥接摘要、两个 Tab 的完整矩阵、原生取消重载和同 Tab 断开重连；两页 2,500 行均在原定 10 秒预算内完整捕获。首轮 FAIL 保留。

本机客户端禁用运行期间的 Run，重复启动由原生菜单阻止，友好重复提示分支未触发。Windows 原生验收沿用 0.5.5 回执；新增共享逻辑通过 Windows CI，不能将 CI 当作 Windows 真机重测。真实 AI 客户端审批 UI、Intel Mac 和 Linux 桌面未在本轮验收。

按平台下载完整包并核对 `SHA256SUMS`。升级后在空闲时通过原生 Script → Cancel / Run 重载固定入口，重新加载 MCP 客户端并枚举新句柄。历史失败回执保留；真实 AI 客户端审批界面和其他设备须独立验收。
