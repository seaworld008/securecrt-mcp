# securecrt-mcp 0.5.2

This patch fixes Xshell command reuse and batch completion, explicit interruption, guarded input context and pre-send delivery evidence. Capture reads newly completed native buffer rows instead of comparing whole screenshots, preventing old history and duplicate output from entering command results. The host loop uses bounded native waits to avoid the observed Python Sleep reference-count defect, and Unicode POSIX commands preserve their UTF-8 bytes through the ANSI input binding. Explicit fresh idle acknowledgement updates only the requesting client’s attachment after timeout or interruption, allowing the next intended command without accepting stale context. Unterminated rows are retained in snapshot, prompt and stream capture, and completed prompt captures preserve attachment reuse. Native state is restored on shutdown, and runtime diagnostics can read the running Xshell executable version without ctypes.

The release also includes the post-0.5.0 MCP dual-era protocol policy, backend support diagnostics, OpenSSH output/interlock hardening and SHA-256 fingerprint corrections described in CHANGELOG.md. Rust MSRV stays at 1.88.

Run upgrade without --force, stop the old script only while idle, and load the matching bridge inside Xshell. Verify doctor --backend xshell and the opt-in desktop smoke before opening production sessions. Scripts loaded in memory do not update when files are replaced.

Xshell remains screen-backed rather than a native PTY. Cross-tab selection requires Single Process Mode; separate processes need their own bridge instances. Unknown outcomes are never replayed or automatically acknowledged. The reproduced Xshell 8.0.0.26 / embedded Python 3.8.6 binding is rejected before native writes; use the vendor-supported external 32-bit Python/pywin32 engine and verify the actual runtime. Version/API diagnostics do not replace desktop acceptance.

Live acceptance: Windows 11 ARM64 10.0.26200, Xshell 8 Build 0110 / product 8.0.0.26, external Python 3.14.2 x86 and pywin32 312; two SSH targets and both MCP protocol eras passed 15 checks per combination. See docs/acceptance/windows-xshell-0.5.1.json for the tested source and hashes. This is exact-runtime Tier 2 evidence, not certification of other Windows/client combinations.

Release archives now include JSON desktop acceptance receipts, and packaging verifies every relative Markdown link resolves to an archived file. The 0.5.1 tag build was cancelled before publication after this missing receipt was found; 0.5.2 retains its Xshell fixes.

Prompt completion now requires observed post-send capture progress before accepting a screen-only prompt match, preventing an unchanged idle prompt from completing with empty output before Xshell redraws.
