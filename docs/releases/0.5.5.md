# securecrt-mcp 0.5.5

本轮修复 Windows 输出捕获和提示符覆盖恢复，增加同一已登录终端上的显式日志加速，并保持已有登录、策略、令牌和客户端审批。

## 改进

- SecureCRT 使用有界逐行接收，延迟正文和原生超时不再被错误报告为完整空输出。命令结束证据、输出完整性和保留截断分别返回。
- Xshell 按原生 Get 的真实换行行为读取，避免额外空行。在滚动缓冲饱和时只接受本次精确标记和完整已交付前缀；命令回显先到时等待开始标记，不猜测历史重叠或重发。
- Windows POSIX 命令及批次可明确设置 `prefer_native_log=true`：SecureCRT 原始 UTF-8 日志和 Xshell UTF-8/BOM UTF-16 会话日志由 Rust 批量读取，减少逐行 SDK 调用和滚动缓冲限制。已有用户日志运行时保持原样并回退到屏幕路径。
- 新鲜完整屏幕令牌保护一次 Enter 的显式提示符恢复；输入、身份、宽度、owner 或完成证据变化时拒绝。
- 原生宿主使用短文件临界区和代次 owner，忙或未决状态不能被过期抢占。所有权状态写入失败或原状态无法验证时停止，旧代次继续运行前检查发送权。旧锁迁移必须明确确认实际脚本已经停止且测试页空闲。
- 文件 IPC 减少固定等待；MCP 返回结构化结果及兼容文本，屏幕上下文可限制返回量，仍使用完整原生帧令牌。
- 大脚本辅助模块提供 UTF-8/LF、0600 暂存、SHA-256 和原子替换；未知结果不重新上传，上传与执行分别确认。
- Windows 安装遇到运行中的 EXE 被锁定时安装到独立摘要目录，保留运行中的旧客户端和现有配置。

## 使用边界

日志加速默认关闭。它会临时保存命令回显和输出到本地私有目录，不用于密码或秘密命令。正常结束会读取最终刷新并清理自己的文件；强杀终端或跳过脚本清理时可能残留日志状态，重载前检查原测试页。Xshell 保留原日志格式和编码设置；改变标记行的时间戳等前缀可能无法确认完成，其最后实际日志文件名查询值也可能在关闭后保留本次路径。不会为了恢复该元数据开启用户日志。

REA 对选定旧 Xshell SDK 的分析与真机探测确认了缓冲坐标、换行和等待差异。本机旧 SDK 的 Sleep 实测约有 200 ms 下限，优化不意味着已经达到原生 SSH 性能；尚无同网络原生 SSH 对照。Mac 为编译后协议和适配器模拟验证，没有 Mac 真机。

## 验证与升级

具体源码/二进制、通过范围与限制见[Windows 验收记录](../acceptance/windows-capture-2026-10-13.md)。Windows 两终端各两个专用测试页的完整矩阵、真实断线重连及生命周期验收通过，Rust/编译后 MCP/Windows 自包含安装/Mac 适配器模拟检查通过。

使用对应平台完整包并核对 Release 的 `SHA256SUMS`。Windows 用户按 `START-HERE.md` 安装，在已确认空闲的测试边界通过真实终端界面取消旧脚本、加载固定入口，并重新加载 MCP 客户端、重新枚举目标。旧句柄不应复用。完整边界见[中文操作指南](../agent-usage.md)、[English guide](../agent-usage.en.md)和[升级说明](../installation.md)。
