# 0.3.0 - production release

0.3.0 is the first stable release of securecrt-mcp. It packages the persistent SecureCRT session workflow, bounded prompt readiness, batch execution, long-output pagination, daemon reuse, and explicit failure/approval boundaries.

## Verified before release

- `cargo fmt --all -- --check`
- strict Clippy with `-D warnings`
- locked Rust tests and release build
- Python adapter and MCP/daemon/fault/package smoke suites
- Windows x64 SecureCRT 9.0.0 with embedded Python 3.8.10
- post-restart acceptance on `php_test`, `php_dev`, and `k8s-master1`
- repeated `hostname`, `uptime`, `pwd` batch execution with independent results
- long-output cursor pagination and `observe` refusal with `sent=false`
- duplicate Bridge start handling with a Chinese already-running dialog

## Production scope

This release is suitable for controlled production diagnostics, release checks, log inspection, and explicitly approved changes through already authenticated SecureCRT tabs. It is not a native SSH/PTY implementation, does not lock the SecureCRT keyboard, and does not replace MCP client approval or remote account authorization.

When prompt context is uncertain, the Bridge returns `context_changed` or an unresolved state and sends nothing further. Operators must inspect the original tab before attaching again or acknowledging idle. MySQL, pagers, REPLs, editors, and password prompts require their own explicit interaction flow rather than POSIX batch commands.

## Upgrade

```powershell
cargo build --locked --release
.\target\release\securecrt-mcp.exe upgrade
.\target\release\securecrt-mcp.exe doctor --offline
```

After upgrade, stop the old SecureCRT script or restart SecureCRT, then run the installed Bridge again. Existing policy, token, and custom deny rules are preserved; `init --force` is not part of a routine upgrade.
